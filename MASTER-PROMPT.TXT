3. CRYPTOGRAPHIC ENGINE, QUOTA-LOCKED SIGNING & QR NORMALIZATION
================================================================================
1. **Key Ring & Discovery (`MasterKeyService`):**
   - Resolve active signing key from `signing_keys` (preferring buyer-specific active key, falling back to global active key, and legacy `K00` from `.env` `HQ_PRIVATE_SIGNING_KEY` / `UNIVERSAL_PUBLIC_VERIFICATION_KEY`).
   - Validate keypairs via `sodium_crypto_sign_publickey_from_secretkey` + `hash_equals`.
   - CLI commands: `php artisan triproof:keys --write`, `php artisan triproof:keys:rotate --key-version=K02 [--buyer=ID]`, and scheduled `php artisan triproof:anchor-merkle` (daily at 01:30).
   - `GET /.well-known/triproof-key.json` (with open CORS headers): ALWAYS publish the active `K00` public key from `.env` even when `signing_keys` is empty, alongside all `active` and `verify_only` keys from `signing_keys`, SHA-256 fingerprints, and key rotation policy.
2. **Canonical Serial Contract (`SerialCryptoService`):**
   - Legacy `K00`: `{FACTORY}-{MACHINE}-{BATCH}-{UNIT:06d}|{PROD_DATE}|{EXP_DATE}`
   - Enterprise V2: `{KNN}-{FACTORY}-{MACHINE}-{BATCH}-{UNIT:06d}|{PROD_DATE}|{EXP_DATE}|DPP:{8-HEX-DIGEST}`
   - `inner_serial = Base64(Ed25519_detached_sign(outer_serial))`
   - `unit_hash = SHA256(outer_serial . "|" . inner_serial)`
   - **Critical Payload Normalization (`normalizePayload`):** Strip `{APP_URL}/v/` wrapper from outer payloads and `TP1:` prefix from inner payloads, and **always run `rawurldecode()`** on extracted path segments so URL-encoded `%7C` pipes convert back to `|` *before* Ed25519 signature verification, `unit_hash` calculation, or database lookup.
3. **6-Step Atomic Quota-Locked Signing (`BatchGenerationService`):**
   - Begin DB transaction -> `SELECT ... FOR UPDATE` on `purchase_orders` -> reject if `count > authorized_quota - generated_count` -> allocate sequential unit numbers -> sign exact N serials -> recompute SHA-256 binary Merkle tree -> update `generated_count` and `merkle_root_hash` -> commit.
4. **QR Sticker Sheets (`BatchExportService` & `resources/views/exports/qr-labels-pdf.blade.php`):**
   - Render paired Outer QR (`{APP_URL}/v/{outer_serial}`, pair code `01`, Error Correction M) and Inner QR (`{inner_serial}`, pair code `11`, Error Correction Q) with unit hash preview and 100% actual-size thermal/A4 print instructions.

4. VERIFICATION STATE MACHINE, 50 KB OFFLINE PACKAGE & BILINGUAL AI
================================================================================
1. **Verification Engine (`VerificationService`):**
   - Enforce idempotency via `sync_uuid`; validate attested device `scan_seq` monotonicity and signature `{syncUuid}|{scanSeq}|{outer}`.
   - Lock serial row (`lockForUpdate()`), verify Ed25519 signature across active + `verify_only` keys and `unit_hash`, and evaluate strict verdict precedence:
     `forged_signature` -> `recalled_batch` -> `expired` -> first claim `verified_clean` -> same-device `owner_repeat_ok` -> store checkout grace `store_grace_ok` (`<= 300s` & `<= 100m`) -> `clone_detected`.
   - On `clone_detected`: mark serial cloned, notify both first and second devices in EN/BN, trigger optional `ALERT_WEBHOOK_URL`, and upsert an `ai_anomaly_reports` record.
   - Web `/verify` and `GET /v/{payload}` perform read-only forensic/passport inspection without claiming device ownership.
2. **Offline Blacklist & Bloom Filter (`OfflineBlacklistService`):**
   - `GET /api/v1/offline-blacklist` and `GET /api/v1/blacklist/delta` return a gzip+Base64 JSON package capped at `50,000` bytes containing recalled batches, cloned serials, key ring, and a `240,000`-bit Bloom filter (`OFFLINE_BLOOM_MAX_BITS=240000`, targeting 30,000 entries as a probable-match warning before exact SQLite lookup).
3. **Bilingual AI & Containment (`AnomalyAnalysisService`, `RecallService`, `ReworkService`):**
   - Detect clone clusters, ghost production attempts, rework lineage gaps, and defect clusters with actionable English and Bangla floor instructions.
   - `RecallService`: surgical `Factory + Machine + Batch` recall updating serial statuses, logging `recall_events`, and pushing `recall_alert` notifications to affected devices.
   - `ReworkService`: CSV/JSON parent-child serial reconciliation (`rework_parent_serial`).
