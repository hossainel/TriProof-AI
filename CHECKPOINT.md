# TriProof AI — compact V2 checkpoint

- **State:** Enterprise V2 implemented locally across Laravel 12, Blade web and native Android; no commit made for V2 in this session.
- **Backend/DB:** additive migrations and models for `signing_keys`, DPP columns, `carton_aggregations`, `carton_units`, `blockchain_anchors`, `device_attestations`; `schema.sql` regenerated. v1 serials remain `K00`; V2 uses `KNN-...|DPP:XXXXXXXX` with the full signed string. Key ring is exposed by well-known/login. Rotation CLI is `triproof:keys:rotate --key-version=K02 [--buyer=ID]` (positional version also supported; Symfony reserves `--version`).
- **Features:** DPP service and admin key ring card; carton aggregate/verify with Merkle inclusion proofs; byte-budget Bloom filter; daily local Merkle anchor command and audit receipts; signed carton and device key for Android; monotonic `scan_seq` replay rejection; clone/recall webhook; public `/v/{payload}` passport with smart-URL outer QR codes; English-only `O1/I1` PDF preserved.
- **Gates:** Laravel **57 tests / 288 assertions**, Pint, Composer validation, Vite build and Blade cache pass. Android **8 JVM tests**, lint, `assembleDebug`, and all **7 API 35 instrumented tests** pass after the Room 1→2 migration (one fake-key fixture was fixed). No physical handset was attached.
- **Bloom constraint:** 30,000 entries fit below 50 KB at 288,000 bits with roughly 1% FPR; the payload reports the measured estimate. A 0.1% filter requires ~54 KB before Base64 and cannot fit the wire cap.
- **Production follow-ups:** physical-handset camera/latency acceptance, secure release signing, production HTTPS/public key pin and real external anchor/webhook credentials.
